# Минимальная сборка FFmpeg для замены кадров

## Go-библиотека

```sh
go get github.com/Warp-net/ffmpeg-stripped
```

`ffmpeg.GetFFmpeg()` возвращает `([]byte, error)` с исполняемым файлом для
текущей платформы. Как и в `payment-engine-lib`, бинарники хранятся в gzip,
встраиваются через `go:embed` и распаковываются при каждом вызове. В приложение
попадает только бинарник выбранной платформы; CGO и загрузка из сети не нужны.

Поддерживаются Linux, macOS и Windows на `amd64` и `arm64`.
На Android, iOS и остальных платформах возвращается `ffmpeg.ErrUnsupported`.

```go
package main

import (
    "log"
    "os"
    "os/exec"
    "path/filepath"
    "runtime"

    ffmpeg "github.com/Warp-net/ffmpeg-stripped"
)

func main() {
    binary, err := ffmpeg.GetFFmpeg()
    if err != nil {
        log.Fatal(err)
    }
    if err := run(binary); err != nil {
        log.Fatal(err)
    }
}

func run(binary []byte) error {
    dir, err := os.MkdirTemp("", "ffmpeg-*")
    if err != nil {
        return err
    }
    defer os.RemoveAll(dir)

    name := "ffmpeg"
    if runtime.GOOS == "windows" {
        name += ".exe"
    }
    path := filepath.Join(dir, name)
    if err := os.WriteFile(path, binary, 0o700); err != nil {
        return err
    }
    cmd := exec.Command(path, "-version")
    cmd.Stdout, cmd.Stderr = os.Stdout, os.Stderr
    return cmd.Run()
}
```

После замены исходных бинарников в каталогах `linux-*`, `macos-*` и `windows-*`
выполните `go generate ./...`, чтобы обновить архивы в `bin/`. Для генерации
нужны `sh` и `gzip`; для использования библиотеки достаточно Go.

Подробное описание исходников, параметров сборки и проверок — в [BUILD.md](BUILD.md).

Собрано 6 ноября 2026 года на Linux x86-64 кросс-компилятором Zig 0.13.0
(Clang 18.1.6). FFmpeg 7.1.2, x264 из снимка исходников, zlib 1.3.1.
Это урезанная сборка для конкретного сценария, а не доказанный абсолютный
минимум размера.

Поддерживается: локальный MP4/MOV с видео H.264, PNG-картинка, преобразование
частоты кадров и наложение картинки, выход MP4/H.264, копирование совместимого
с MP4 звука без декодирования. Других видеодекодеров, сети и устройств захвата нет.
Ассемблерные оптимизации отключены; это может существенно снижать скорость.
Кодировщик x264 собран только для 8-битного YUV 4:2:0.

Linux использует musl и полностью статическую линковку. Windows требует
системные DLL Windows, включая Universal CRT, но не отдельные DLL FFmpeg/x264/zlib.
macOS использует только /usr/lib/libSystem.B.dylib, целевая версия — macOS 11+.
Сборки macOS не нотарифицированы.

## Проверенная команда

Картинка должна быть непрозрачной и иметь размер видео.

```sh
./ffmpeg -i input.mp4 -loop 1 -framerate 25 -i frame.png \
  -filter_complex "[0:v]fps=25,setpts=PTS-STARTPTS[v];[v][1:v]overlay=0:0:shortest=1:enable='eq(mod(n,25),24)'[out]" \
  -map '[out]' -map '0:a?' -r 25 \
  -c:v libx264 -crf 18 -pix_fmt yuv420p -c:a copy output.mp4
```

Выходной `-r 25` указан явно: в проверке без него последний кадр имел нулевую
длительность в MP4 и не возвращался при декодировании.

## Проверки

Linux x86-64: запуск, создание и декодирование MP4, проверка всех 50 кадров
двухсекундного ролика: индексы 24 и 49 белые, остальные чёрные.
Сохранение AAC проверено сравнением байтов всех аудиопакетов до и после обработки.
Для остальных целей проверены формат файла, архитектура и внешние зависимости;
подробный итог проверки Windows в файле TESTS.txt.

Размеры в SIZES.csv относятся только к исполняемому файлу, без архива и исходников.
SHA256SUMS содержит контрольные суммы файлов комплекта.

## Исходники и повторная сборка

Рядом с архивом бинарников предоставляется ffmpeg-minimal-sources.tar.xz:
полные использованные исходники, скрипты сборки и программы проверки.
Распаковать в новый каталог. Установить make, pkg-config и Python 3;
скачать и распаковать Zig в work/zig-linux-x86_64-0.13.0:

```sh
curl -fL https://ziglang.org/download/0.13.0/zig-linux-x86_64-0.13.0.tar.xz -o zig.tar.xz
echo 'd45312e61ebcc48032b77bc4cf7fd6915c11fa16e4aad116b66c9468211230ea  zig.tar.xz' | sha256sum -c -
tar -xf zig.tar.xz -C work
bash work/build-minimal.sh linux-x86_64 x86_64-linux-musl x86_64-linux-musl linux x86_64
bash work/build-minimal.sh linux-arm64 aarch64-linux-musl aarch64-linux-musl linux aarch64
bash work/build-minimal.sh windows-x86_64 x86_64-windows-gnu x86_64-w64-mingw32 mingw32 x86_64
bash work/build-minimal.sh windows-arm64 aarch64-windows-gnu aarch64-w64-mingw32 mingw32 aarch64
bash work/build-minimal.sh macos-x86_64 x86_64-macos.11.0 x86_64-apple-darwin darwin x86_64
bash work/build-minimal.sh macos-arm64 aarch64-macos.11.0 aarch64-apple-darwin darwin aarch64
```

Скрипт запускает make -j4. Запускать команды последовательно.
В configure FFmpeg сделаны две правки для линкера Zig: убраны Darwin-флаги
`-dynamic,-search_paths_first` и обход ошибки GNU binutils
`--pic-executable,-e,mainCRTStartup` для Windows x86-64. Полные исходники содержат
эти правки. x264 и zlib не изменялись.

Сборка FFmpeg с x264 распространяется по GPL v2 или более поздней версии.
Тексты лицензий находятся в LICENSES; исходники доступны в указанном архиве.

# Как собраны минимальные бинарники FFmpeg

Эти шесть исполняемых файлов собраны из исходников для обработки локального
видео: декодирование H.264 из MP4, наложение PNG на выбранные кадры и сохранение
результата в MP4/H.264. Звук копируется без перекодирования.

Сборка выполнена 6 ноября 2026 года на Linux x86-64. Для каждой платформы и
архитектуры создан отдельный бинарник. Это компактная конфигурация под указанный
сценарий, а не универсальная сборка FFmpeg и не гарантированный минимум размера.

## Исходники и инструменты

| Компонент | Версия / источник | Назначение |
|---|---|---|
| FFmpeg | 7.1.2, тег `n7.1.2` | Чтение и запись контейнера, декодирование, фильтры, CLI |
| x264 | Снимок `mirror/x264`, ветка `master`, загруженный в день сборки | Кодирование H.264 |
| zlib | 1.3.1 | Декодирование сжатых данных PNG |
| Zig | 0.13.0 для Linux x86-64 | Кросс-компилятор, линкер, архиватор и целевые библиотеки C |
| Clang в составе Zig | 18.1.6 | Компиляция C-кода |

Исходники: [FFmpeg](https://github.com/FFmpeg/FFmpeg/tree/n7.1.2),
[x264](https://github.com/mirror/x264), [zlib](https://github.com/madler/zlib/tree/v1.3.1).
Точный снимок x264 находится в предоставленном архиве исходников: повторная
загрузка ветки `master` может дать другую версию. SHA-256 исходных загруженных
архивов записан в `SOURCE-SHA256SUMS`.

## Порядок сборки

Для каждой цели создаются собственные каталоги сборки и установки зависимостей.
Обёртки `cc`, `ar` и `ranlib` вызывают соответствующие инструменты Zig;
компилятор получает `-target` из таблицы выше. `PKG_CONFIG_PATH` и
`PKG_CONFIG_LIBDIR` указывают только на зависимости текущей цели.

Сначала собирается статическая zlib с оптимизацией `-Os`. Затем собирается
статическая x264 со следующими параметрами:

```sh
--enable-static
--disable-cli
--disable-opencl
--disable-asm
--bit-depth=8
--chroma-format=420
--extra-cflags=-Os
```

Отдельная утилита x264 не создаётся. Кодировщик ограничен 8-битным YUV 4:2:0,
который используется в проверенной команде обработки видео.

После этого собирается FFmpeg. Общая конфигурация:

```sh
--enable-cross-compile
--disable-everything
--disable-autodetect
--disable-network
--disable-doc
--disable-debug
--disable-ffplay
--disable-ffprobe
--disable-avdevice
--disable-shared
--enable-static
--enable-small
--disable-asm
--disable-stripping
--enable-gpl
--enable-libx264
--enable-zlib
--enable-protocol=file
--enable-demuxer=mov,image2,png_pipe
--enable-muxer=mp4
--enable-decoder=h264,png
--enable-encoder=libx264
--enable-parser=h264,png
--enable-filter=buffer,buffersink,fps,setpts,overlay,scale,format,null
--pkg-config-flags=--static
```

Дополнительно передаются инструменты `--cc`, `--ar`, `--ranlib`, целевые
`--target-os` и `--arch`, а также пути к заголовкам и статическим библиотекам
zlib и x264. Компиляция запускается через `make -j4`: цель `ffmpeg` для Linux
и macOS, `ffmpeg.exe` для Windows.

`--disable-everything` выключает компоненты, после чего нужные включаются явно.
Некоторые вспомогательные компоненты FFmpeg добавляет автоматически как
зависимости программы и фильтров. Поэтому приведённый список `--enable-filter`
не является полным списком фильтров в готовом бинарнике. Точная конфигурация
каждой сборки сохранена в соответствующем `config.mak` и доступна через
`ffmpeg -version`.

## Линковка и уменьшение размера

Библиотеки FFmpeg, x264 и zlib включены в исполняемые файлы. Отдельные `.so`,
`.dll` или `.dylib` этих библиотек для запуска не нужны.

На Linux используется musl и флаги линкера `-static -s`. Полученные ELF-файлы
полностью статические, таблицы символов удалены. На Windows также передаются
`-static -s`, но остаются импорты системных DLL Windows, включая Universal CRT,
`KERNEL32.dll`, `SHELL32.dll` и `bcrypt.dll`.

На macOS используется `-Wl,-S`: удаляется отладочная информация. Единственная
динамическая зависимость, найденная в Mach-O, — `/usr/lib/libSystem.B.dylib`.
Целевая версия ОС — macOS 11 или новее. Нотарификация не выполнялась.

`--disable-stripping` выключает отдельный завершающий вызов утилиты `strip`
из сборки FFmpeg: вместо него используются указанные флаги линкера для каждой
платформы. Это не означает сохранение отладочной информации во всех файлах.

Основная экономия размера достигнута отключением большинства кодеков,
контейнеров, фильтров, сети, устройств, документации и дополнительных программ.
`--enable-small` включает оптимизацию FFmpeg под размер. Ассемблерные
оптимизации отключены и в FFmpeg, и в x264; это упрощает сборку для шести целей,
но может существенно снизить скорость. Производительность отдельно не измерялась.

## Изменения для совместимости с линкером Zig

В `configure` FFmpeg сделаны две правки:

1. Для Darwin удалено добавление `-Wl,-dynamic,-search_paths_first`:
   линкер Zig отвергал `-dynamic`, а динамическая системная линковка уже
   используется по умолчанию.
2. Для Windows x86-64 удалено добавление
   `-Wl,--pic-executable,-e,mainCRTStartup`. Это обход особенности GNU binutils;
   линкер Zig отвергал `--pic-executable`. Настройки `--dynamicbase`,
   поддерживаемые линкером, сохранены.

Эти правки входят в предоставленные исходники. Исходники x264 и zlib не менялись.
При сборке zlib для macOS архиватор и его флаги передавались в `make` явно
(`AR=... ARFLAGS=rc`), чтобы не требовался Apple `libtool` на Linux.

## Проверки готовых файлов

| Цель | Выполненные проверки |
|---|---|
| Linux x86-64 | Запуск, кодирование PNG в MP4/H.264, декодирование и замена кадров, сохранение AAC |
| Windows x86-64 | Запуск и замена кадров под Wine, проверка полученного видео |
| Linux ARM64 | Формат ELF, архитектура, статическая линковка; без запуска |
| Windows ARM64 | Формат PE, архитектура и импорты DLL; без запуска |
| macOS x86-64 и ARM64 | Формат Mach-O, архитектура и динамические зависимости; без запуска |

В тесте замены кадров использовалось двухсекундное видео из 50 чёрных кадров
при 25 FPS и белая PNG-картинка. После обработки декодированы все 50 кадров:
кадры с индексами 24 и 49 белые, остальные чёрные. Этот тест пройден Linux
x86-64 и Windows x86-64 под Wine.

На Linux отдельно обработан ролик со звуком AAC. Содержимое аудиопакетов до и
после обработки совпало побайтово; SHA-256 обеих последовательностей:

```text
73fc5e586b56dfb9f275874d6cf43ca1d00054761e822fca557878d51d4f1a75
```

Проверка Windows под Wine не заменяет проверку на настоящей Windows. Для ARM64
и macOS работоспособность запуском не подтверждена.
